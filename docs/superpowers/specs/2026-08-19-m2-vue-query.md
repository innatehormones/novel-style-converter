# M2 — 把 workflows store 迁移到 TanStack Query (vue-query)

日期：2026-08-19
范围：\`src/stores/workflows.ts\` + \`src/views/TransformationNovelDetail.vue\` + \`src/components/RegeneratePreviewDialog.vue\` + \`src/main.ts\`

## 背景

\`workflows.ts\` 当前用 6 个 \`ref<Map<K, V[]>>\` 字段手写"按 key 缓存 + 加载"模式：

\`\`\`\`\`\`\`\`\`ts
const byTn = ref<Map<number, WorkflowSummary[]>>(new Map());
const chaptersByBatch = ref<Map<number, WorkflowChapterRow[]>>(new Map());
const sourcesByTn = ref<Map<number, SourceChapterRow[]>>(new Map());
const resultsByTnChapter = ref<Map<string, ChapterWorkflowResultRow[]>>(new Map());
const previewsByBatchChapter = ref<Map<string, ChapterPreviewRow[]>>(new Map());
const promotedByBatch = ref<Map<number, DataAsset[]>>(new Map());  // 死数据,无人读
\`\`\`\`\`\`\`\`\`

6 个 \`loadXxx\` 函数是 1 行模板：

\`\`\`\`\`\`\`\`\`ts
async function loadSources(tnId: number) {
  sourcesByTn.value.set(tnId, await listTransformationSourceChapters(tnId));
}
\`\`\`\`\`\`\`\`\`

3 处 5s / 2s 轮询走 \`useIntervalFn\`。

mutation（create / stop / retry / promote / regeneratePreview / commitPreview / discardPreview / deleteWorkflow）
手写在 store 函数体内，after-mutation 要靠 loadRefetch 手动触发：

\`\`\`\`\`\`\`\`\`ts
async function stop(batchId: number) {
  const w = await stopWorkflow(batchId);
  await refresh(batchId);   // 手动重新拉
  return w;
}
\`\`\`\`\`\`\`\`\`

## 目标

迁移到 **TanStack Query (vue-query)**，理由：

1. **行业事实标准**：TanStack Query GitHub 42k+ stars、npm 周下载 5M+；Vue 3 新项目里"按 key 缓存 + 后端同步数据"场景 90% 选它
2. **根治**当前手写模式的"维护性问题"：6 个 Map + 6 个 loadXxx + 手写 invalidate 触发是 Vue 2 时代 Options API 遗留模式，新项目基本不这么写
3. 自动获得 \`loading / error / data\` 三态、\`refetchInterval\` 替代 \`useIntervalFn\`、\`invalidate\` 替代手写 \`loadXxx\`、dedupe、devtools

## 设计

### 依赖

- 加 \`@tanstack/vue-query@5\` (~12KB gzipped)

### \`src/main.ts\` 注册

\`\`\`\`\`\`\`\`\`ts
import { VueQueryPlugin, QueryClient } from '@tanstack/vue-query';

const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      // IPC 调用失败不要盲目重试 —— 后端错误就是错误。
      retry: false,
      // 5s 内的重复 mount 不重新拉,防止详情页来回切时频繁 IPC。
      staleTime: 5000,
      // 窗口聚焦时不自动重拉(避免后端意外负载)。
      refetchOnWindowFocus: false,
    },
  },
});

const app = createApp(App);
app.use(createPinia());
app.use(router);
app.use(VueQueryPlugin, { queryClient });
\`\`\`\`\`\`\`\`\`

### \`src/stores/workflows.ts\` —— 缩成薄壳

\`store\` 不再持有"按 key 的数据 Map"，但保留"流程编排职责"：mutation 调 IPC + 触发相关 query invalidate。

\`\`\`\`\`\`\`\`\`ts
export const useWorkflowsStore = defineStore('workflows', () => {
  const queryClient = useQueryClient();

  async function createWorkflowAndInvalidate(payload: CreateWorkflowInput) {
    const w = await createWorkflow(payload);
    await queryClient.invalidateQueries({ queryKey: ['workflows', w.tn_id] });
    return w;
  }

  async function stopWorkflowAndInvalidate(batchId: number) {
    const w = await stopWorkflow(batchId);
    await queryClient.invalidateQueries({ queryKey: ['workflowChapters', batchId] });
    await queryClient.invalidateQueries({ queryKey: ['workflows'] });
    return w;
  }

  // retry / deleteWorkflow / promote / regeneratePreview / commitPreview / discardPreview 同模式
  // 删除所有 Map 字段、loadXxx 函数、loading / error 通用状态
  // promotedByBatch 整个删掉(死数据)

  return {
    create: createWorkflowAndInvalidate,
    stop: stopWorkflowAndInvalidate,
    retry,
    deleteWorkflow,
    promote,
    regeneratePreview,
    commitPreview,
    discardPreview,
  };
});
\`\`\`\`\`\`\`\`\`

注：mutation 留在 store 是因为它们涉及业务逻辑编排（IPC + invalidate），不在 view 里散落。
删除 store.ts 中 \`loading / error\` 通用 ref —— 用 \`useMutation\` 的 \`isLoading\` / \`error\` 局部状态。

### \`src/views/TransformationNovelDetail.vue\` —— 读侧改 useQuery

**Workflow 列表（5s 轮询）**：

\`\`\`\`\`\`\`\`\`ts
// before
const sources = computed(() => store.sourcesByTn.get(tnId.value) ?? []);
const workflows = computed(() => store.byTn.get(tnId.value) ?? []);

// after
const sources = useQuery({
  queryKey: ['transformationSourceChapters', tnId],
  queryFn: () => listTransformationSourceChapters(tnId.value),
  refetchInterval: 5000,
  select: (rows) => rows ?? [],
});

const workflows = useQuery({
  queryKey: ['workflows', tnId],
  queryFn: () => listWorkflows(tnId.value),
  refetchInterval: 5000,
});

// 模板读 sources.data / workflows.data
\`\`\`\`\`\`\`\`\`

**章节列表（2s 轮询）**：

\`\`\`\`\`\`\`\`\`ts
const chapters = useQuery({
  queryKey: ['workflowChapters', selectedWorkflowId],
  queryFn: () => listWorkflowChapters(selectedWorkflowId.value!),
  enabled: computed(() => selectedWorkflowId.value !== null),
  refetchInterval: 2000,
});
\`\`\`\`\`\`\`\`\`

**章节结果（on-demand）**：

\`\`\`\`\`\`\`\`\`ts
const results = useQuery({
  queryKey: ['chapterWorkflowResults', tnId, openSourceChapterId],
  queryFn: () => listChapterWorkflowResults(tnId.value, openSourceChapterId.value!),
  enabled: computed(() => openSourceChapterId.value !== null),

\`\`\`\`\`\`\`\`\`

复合 key 天然对齐 vue-query 的 array key 模式。

### 删除的代码

\`store/workflows.ts\`：
- 6 个 Map ref
- 6 个 loadXxx 函数
- promotedByBatch Map + loadPromotedByBatch + promote 内的 prepend（死数据）
- \`refresh(batchId)\` —— 由 invalidate 替代
- 通用 loading / error ref

\`views/TransformationNovelDetail.vue\`：
- \`workflowListPoll\` / \`chapterPoll\` 两个 \`useIntervalFn\` 句柄
- \`isBatchLive\` / \`POLLABLE_STATUSES\` / \`ACTIVE_CHAPTER_STATUSES\` 计算属性 —— 改在 \`useQuery\` 的 \`select\` / \`refetchInterval\` 配置里表达

## 复合 key 适配

旧 store 用 \`${tnId}:${chapterId}\` 字符串拼接作 key。vue-query 用 array：
\`\`\`\`\`\`\`\`\`ts
// before
resultsByTnChapter.value.get(`${tnId}:${chapterId}`)
// after
useQuery({ queryKey: [''chapterWorkflowResults'', tnId, chapterId], ... })
\`\`\`\`\`\`\`\`\`

不需 \`toKey\` 转换器，vue-query 自动 JSON 序列化 array 作缓存 hash。

## 轮询迁移

\`\`\`\`\`\`\`\`\`ts
// before
const workflowListPoll = useIntervalFn(() => {
  void store.loadByTn(tnId.value);
  void store.loadSources(tnId.value);
}, 5000);

// after
useQuery({ queryKey: [''workflows'', tnId], queryFn, refetchInterval: 5000 });
useQuery({ queryKey: [''transformationSourceChapters'', tnId], queryFn, refetchInterval: 5000 });
\`\`\`\`\`\`\`\`\`

vue-query 的 refetchInterval 在 \`enabled: false\` 时自动停，无需手动 pause / resume。

## 风险评估

| 风险 | 评估 |
|---|---|
| 新依赖 | \`@tanstack/vue-query@5\` ~12KB,稳定维护中 |
| 概念迁移 | Pinia → Pinia + QueryClient 两套机制，view 读侧写法变化（computed → useQuery），需小心 |
| response shape | 旧 store \`get(k) ?? []\` 在 key 不存在时返回 \`[]\`；vue-query 默认 \`data\` 是 \`undefined\`，需 \`select\` 或读 \`(data ?? [])\` |
| loading / error 三态 | 现在所有调用方都用 \`store.loading\` / \`store.error\`（实际是 store 通用 ref，未被读方真正用）—— 直接删，无外部依赖 |
| 轮询死循环 / 重复请求 | vue-query 内置处理 |
| invalidate 范围 | 6 个 query 的 key 结构约定要清楚；mutation 调用方负责 \`invalidate\` 哪些 key —— 用 \`onSuccess\` 在 store 里集中处理 |
| 类型 | \`useQuery<TData, TError>\` 泛型推断 OK |
| QueryClient 单例 vs 多实例 | 单例足够；后续如需 per-request client 再讨论 |
| devtools | vue-query 有 devtools，但 Tauri WebView 不一定支持 —— 留 TODO |

## 拒绝的范围

- ❌ 一并迁移其他 store（library / models / prompts / chapters）的按 key 缓存——本 spec 仅限 workflows
- ❌ 引入 \`persistQueryClient\` 做离线缓存——目前 IPC 直连后端，不涉及离线场景
- ❌ 重写 mutation 为 \`useMutation\` —— 业务编排留在 store 更清晰；view 仅触发 \`store.create()\` 即可
- ❌ 迁移期间保留兼容层（store.workflows.byTn 仍可用）—— 直接删干净，避免双轨制
